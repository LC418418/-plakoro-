# 爬塔平衡模擬器

呢個資料夾**唔屬於遊戲本體**。`index.html` 唔會載入呢度任何嘢，玩家永遠見唔到。
純粹係開發時用嚟調數值嘅工具。

## 做咩用

改爬塔難度嘅時候，靠自己試玩幾局係量唔準嘅 —— 通關率 50% 定 65%，
玩十局都分唔出。呢個模擬器用**遊戲本身嘅戰鬥引擎**跑成千局，直接量到真實通關率。

模擬嘅係一個「識玩但唔會神操作」嘅玩家：

- 每回合揀期望值最高嗰招（命中率 × 傷害，打弱點加權）
- 上場嗰隻血少過兩成、而有健康隊友就換人
- 打低對手一隻之後有**免費換人**機會：上場嗰隻血少過六成就換返隻精神啲嘅
- 獎勵優先攞遺物 > 招式強化 > 新招 > 骰晶片
- 遺物滿咗（8 件）就掉最冇稀有度嗰件，新嗰件唔夠好就索性唔換
- 進化唔到嘅寶可夢夠場數就特訓，血同傷害隨機揀一樣
- 四天王之間有隊友低過七成血、又買得起就買補給
- 商店有錢就買，血少就買傷藥（道具排喺遺物同招式後面，唔會食晒啲錢）
- 道具：升級器即刻用、出戰有人倒咗就用復活藥丸、平均血低過 55% 先用厲害傷藥
- 走地圖時隨機揀下一個節點

所以出嚟嘅數字係一個**中間水平**：識用屬性剋制、換人時機同骰子工房配骰嘅人會高過呢啲數，
求其亂打會低啲。

## 點跑

第一次要裝 Playwright（只需做一次）：

```bash
cd tools && npm install
```

`gendex.py` 同 `fetchdex.py` 仲要 Pillow：`pip install Pillow`。

### 量度而家嘅通關率

```bash
node tools/measure.mjs            # 1200 局，困難
node tools/measure.mjs 1400 0     # 1400 局，困難
node tools/measure.mjs 900 1      # 900 局，魔鬼
```

輸出：

```
章節   行到    打低    通關率   館主場勝率  未見館主就死  遺物/章
第 1 館   6000   3970     66%       68%           3%      1.63
第 2 館   3970   2503     63%       67%           6%      1.62
第 3 館   2503   1492     60%       64%           6%      1.55
...

四天王     52     10     19%    （4 連戰 + 冠軍）

8 館全通：1%　真・全通（連冠軍）：0%

四天王入場：2245.5 金・8 件遺物・平均買 2.9 次補給
陣亡位置：天王1 0　天王2 1　天王3 0　天王4 7　冠軍 34
```

「通關率」＝ 行到嗰章嘅局數入面，成功打低道館主嘅比率。
途中俾雜魚打死都當冇通關（因為一樣打唔到道館主）。

「館主場勝率」同「未見館主就死」係**用嚟分辨凹位嘅來源**（階段 3 加）：
通關率凹咗，可能係嗰個館主本身太硬，亦都可能係成章雜魚太強，兩樣調唔同嘅掣。
階段 3 就係靠呢兩欄先發現城都第 3 館同豐緣第 5 館嘅通關率（30% / 32%）
根本唔關雜魚事 —— 館主場勝率得 32% / 29%，而未見館主就死只係 10% / 19%。

「遺物/章」係**淨增長**。遺物有上限（`RELIC_MAX`，而家 8 件），
多數局第 4-5 章就已經滿曬，所以之後嘅數字自然會跌近零 ——
唔係代表冇遺物拎，係代表之後每一件都要換走一件。

「8 館全通 1%」睇落好低，但呢個係八章制嘅算術結果，唔係太難：
每章 55% 嘅話，連過八關就係 0.55⁸ ≈ 0.8%，同舊嗰個四章版差唔多。

「陣亡位置」睇得出四天王段落邊度先係真牆。而家係冠軍。

### 試唔同數值（唔使改 index.html）

```bash
N=800 node tools/sweep.mjs '[
  {"dmg":{"all":1.0}},
  {"dmg":{"all":1.0},"dmgAct":[1,1,1,1.15]},
  {"dmg":{"all":1.1},"hp":{"all":1.05}}
]'
```

倍率 `1.0` 就係 `index.html` 而家嘅數值。可以調嘅嘢：

| 欄位 | 意思 |
|---|---|
| `curve` | **主力旋鈕**：敵人強度曲線嘅端點，`{"gym":{"hp1":1100}}`。見下面 |
| `actTune` | **主力旋鈕**：逐章微調，`{"hp":[…8 格…],"dmg":[…8 格…]}`。⚠ **三個世代共用** |
| `genTune` | **校城都／豐緣就係用呢個**：淨係郁 `GEN=` 嗰個世代嘅逐章修正，寫法同 `actTune` |
| `focus` | 覆蓋嗰個世代嘅 `TYPE_FOCUS`，`{"無":0.3}`（淨係寫低嘅屬性會變） |
| `dmg` | 敵人傷害倍率，`{all:1.2}` 或者逐個 tier `{mob:1.1, gym:1.3}` |
| `hp` | 敵人血量倍率，寫法同上 |
| `dmgAct` | 再按章節乘一次，`[第1章 … 第8章]`（同 `actTune.dmg` 重疊，試嘢先用） |
| `hpAct` | 同上，血量版 |
| `post` | 每場勝利回幾多血（最大 HP 百分比） |
| `rest` | 篝火回血 |
| `badgeHeal` / `badgeHp` | 拎徽章時回血 / 加最大 HP |
| `diff0` | 覆蓋「困難」難度嘅倍率，例如 `{"heal":0.9}` |
| `diff1` | 覆蓋「魔鬼」難度。`hp` / `dmg` 可以寫 8 格陣列逐章唔同 |
| `set` | 直接寫死某個 tier 嘅陣列，用嚟單獨郁一章：`{"gym":{"nm":[…],"hp":[…]}}` |

### 兩個主力旋鈕（八館改版之後就係靠呢兩個）

`index.html` 入面**冇咗**逐章嘅數字表。敵人強度而家係一條公式：

```
第 a 章 = 起點 × (終點 ÷ 起點) ^ (a ÷ 7)        再乘 ACT_TUNE[a]
```

- `TIER` 每個 tier 得 4 個數：`hp0` `hp1` `nm0` `nm1`（第 1 章同第 8 章）。
  改條曲線嘅**大方向**（成局係咪一路難上去）就郁呢啲。
- `ACT_TUNE` 兩行 8 格，1 = 完全跟曲線。某一章單獨凸咗／凹咗先郁呢度。

⚠ `TIER.gym.hp0/hp1` 係**成隊道館主嘅總血量**，唔係單隻。單隻血由遊戲自己
除返嗰章帶幾多隻（前半 2 隻、後半 3 隻），所以「帶多咗一隻」唔會再喺
條曲線度整個凹位出嚟。魔鬼難度全程 3 隻，多出嗰隻係實打實多一隻嘅血。

```bash
N=3000 node tools/sweep.mjs '[
  {"curve":{"gym":{"hp1":1000}}},
  {"actTune":{"hp":[0.92,1,1.08,1.30,1.12,1.06,1,0.94]}}
]'
```

量魔鬼要開埋 `DIFF=1`：

```bash
DIFF=1 N=6000 node tools/sweep.mjs '[{"diff1":{"hp":[0.97,0.95,0.93,1.02,1.12,1.16,1.20,1.22]}}]'
```

搵到啱嘅組合之後，改返 `index.html` 入面 `TIER` 嘅端點同 `ACT_TUNE`，
再跑 `measure.mjs` 確認。

### 第三個旋鈕：世代修正（`GEN_TUNE`，階段 3 加）

上面兩個旋鈕**三個世代共用**。但同一條曲線落三個世代，出嚟嘅通關率差好遠 ——
道館屬性次序唔同、每個屬性有幾多隻可以用亦都唔同。所以再加一層：

```
第 a 章 = 曲線 × ACT_TUNE[a] × GEN_TUNE[a]
                  ↑ 八章嘅形狀      ↑ 呢個世代嘅修正（REGIONS[g].tune）
```

`GEN_TUNE` 由 `setGen()` 綁（同 `TYPE_FOCUS` 一樣），關都嗰份全部係 1
（曲線本身就係喺關都度調出嚟嘅，佢就係基準）。四天王同冠軍（`flat` tier）
**唔食呢個修正**，同 `ACT_TUNE` 一樣嘅道理。

```bash
GEN=1 N=4000 node tools/sweep.mjs '[{"genTune":{"hp":[1.12,1.22,0.78,1,1,1,1,1]}}]'
```

⚠ **校城都／豐緣一定要行 `genTune`，唔好行 `actTune`** —— `actTune` 一郁
就連關都一齊拉，而關都嗰份係已經定咗案嘅。

## 樣本數要跑幾多

**跑 500 局同跑 1400 局，用嘅 AI usage 一模一樣**（輸出都係同一舊細細嘅 JSON），
分別只係電腦行耐啲。而細樣本雜訊大，反而要多試幾轉先調得準 —— 嗰啲來回先真係燒 usage。

| 局數 | 時間 | 第 8 章樣本 | 誤差 |
|---|---|---|---|
| 1500 | ~60s | ~30 | ±18% |
| 3000 | ~115s | ~60 | ±13% |
| 6000 | ~250s | ~120 | ±9% |

八章制之後尾章嘅樣本數細好多（要連過七關先行到），所以**建議用 3000 起跳，
定案前跑一次 6000**。留意第 6-8 章數字跳 ±10 點係正常，睇趨勢唔好睇單次。

## 目前目標

目標係一個**範圍**，唔係一個點 —— 後面幾章嘅樣本數細（多數局數行唔到咁遠），
量到嘅數字本身就會跳 ±10，追死一個數字係追緊雜訊。

| | 第 1-2 館 | 第 3-5 館 | 第 6-8 館 | 四天王 |
|---|---|---|---|---|
| 困難 | 55-70% | 45-60% | 40-55% | ≤50% |
| 魔鬼 | 35-50% | 25-40% | 20-35% | ≤50% |
| 遺物 | 每章 1-2 件，第 4-5 章上限 8 件封頂 | | | |

⚠ 八章嘅目標比舊嗰個四章版**鬆好多**，唔係抄舊數字。因為要連過八關：
每章 45% 嘅話，八章全通只係 0.45⁸ ≈ 0.17%（600 局先有一局）；
每章 55% 先大約 0.8%，同舊嗰個四章版差唔多。

「四天王」＝ 打低四個道館主嘅局數入面，有幾多完成 4 連戰 + 冠軍。
呢段冇篝火冇商店，每場之間淨係回 15% HP，係一場消耗戰 ——
唯一嘅補給就係開戰前用金幣買（`E4_HEAL_COST`，價錢每用一次升一級）。

實測 16%（困難）／ 29%（魔鬼），入到 ≤50% 嘅範圍。
⚠ **呢個數字樣本天生極細**：八章制之下，跑 6000 局先得 ~55 局行到四天王
（誤差 ±13），跳十幾點都可能只係雜訊，唔好見到跌就即刻加返上去。
要再郁嘅話，旋鈕有 `E4_HEAL`、`E4_HEAL_COST`、同 `TIER.e4` / `TIER.champ`
（呢兩個 tier 標咗 `flat:true`，**唔食 `ACT_TUNE`** —— 佢哋唔屬於任何一章）。

## 調數值嗰陣要記住三件事

**一、郁一章會連帶影響之後嗰幾章。** 前面難咗，行得到後面嘅隊伍本身就強啲，
所以後面反而會顯得易咗。試過第 2 章由 46% 拉落 36%，第 4 章就自己彈上 48%。
要一次過睇齊八個數，唔好逐章追 —— 八章制呢個效應仲明顯，
第 4 章嘅 `ACT_TUNE` 由 1.10 加到 1.26，第 7-8 章自己由 47/41 升到 47/45。

**二、對倍率極度敏感，尤其係傷害。** 行到後面嘅係最強嗰幾 %，人數本身好薄，
加少少就冧一大片。實測（魔鬼第 1 章，6000 局，樣本足）：

| 改乜 | 通關率 |
|---|---|
| `hp` 0.93 / `dmg` 0.95（基準） | 50-52% |
| `hp` 0.95 | 42% |
| `dmg` 0.96（**淨係加 0.01**） | 35% |

**傷害嘅級距係血量嘅兩倍狠**，因為敵人一擊夠唔夠打死你係一個「過／唔過」嘅門檻。
調嘅時候血量一次行 0.02-0.05、傷害一次行 0.01-0.02，同埋兩樣分開試。

**三、跑幾多局係完全唔影響 AI usage。** 跑 3000 局同跑 8000 局，返嚟都係同一舊
細細嘅 JSON，分別淨係部電腦行耐幾十秒。所以**一次 sweep 塞多幾組設定去試**，
唔好一次試兩三組 —— 局數細、組數少先真係燒 usage（因為要多試幾轉）。

**四、（階段 3 加）凹位先要分清楚係「館主」定「雜魚」。** 通關率係一個乘積：
`(1 - 未見館主就死) × 館主場勝率`。兩樣調唔同嘅掣，而且睇通關率本身係分唔出嘅。
階段 3 一開頭跟住計劃書估「一般系道館個 `TYPE_FOCUS` 開得太高」，
跑咗六組 focus 先證實估錯咗 —— 拉到 0 都淨係郁到 3 點。有咗呢兩欄就一眼睇得出。

## ✅ 階段 3：三個世代嘅平衡（2026-08）

### 掘到嘅嘢：「無」系館主永遠唔會能量不足

城都第 3 館（小茜・無）30%、豐緣第 5 館（千歲・無）32%，兩個都凹到見底，
而其餘幾章都喺目標範圍。計劃書估係「一般系道館個 `TYPE_FOCUS` 開得太高，
撞到大奶罐／幸福蛋／請假王嗰批好硬嘅」。**跑咗六組 focus，證實估錯咗**：

| 世代・館 | focus 基準 | 0.35 / 0.45 | 0.15 / 0.25 | 0 |
|---|---|---|---|---|
| 城都第 3 館 | 30% | 29% | 32% | 33% |
| 豐緣第 5 館 | 32% | 29% | 32% | 30% |

拉到 0（成章一隻「無」系雜魚都冇）都淨係郁到 3 點 —— 即係凹位根本唔喺雜魚度。
加咗「館主場勝率 / 未見館主就死」兩欄之後一眼睇穿：

| | 館主場勝率 | 未見館主就死 |
|---|---|---|
| 城都第 3 館 | **32%**（鄰章 73-88%） | 10% |
| 豐緣第 5 館 | **29%**（鄰章 54-77%） | 19% |

真正原因喺 `payCost`：**「無」係萬用能量**，所以「無」系嘅招式（`cost` 全部係
`無`）**任何骰面都找得掂**。其他屬性嘅敵人成日擲唔夠色而放空，「無」系永遠唔會。
一個「無」系館主等於一個「唔會失手」嘅館主，喺中段大約值 **-25 到 -30 點**通關率。

⚠ 所以**擺一個「無」系道館落中後段之前要先諗定**（關都個「無」係第 1 館，
所以一直冇事）。而家係喺 `GEN_TUNE` 嗰格補返，冇改規則 ——
改規則（例如「無」系敵人唔准當萬用）會連玩家自己嗰邊一齊改，留返之後再講。

### 結果（校完之後）

改咗嘅嘢淨係 `REGIONS[1].tune.hp` 同 `REGIONS[2].tune.hp` 兩行，
**關都一個數都冇郁**，`TIER` / `ACT_TUNE` / `DIFFS` 全部原封不動。

| `tune.hp` | 第1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 |
|---|---|---|---|---|---|---|---|---|
| 城都 | 1.12 | 1.22 | **0.78** | 1 | 1 | 1 | 1 | 1 |
| 豐緣 | 0.92 | 1.06 | 1 | 1 | **0.78** | 1 | 1 | 1 |

`tune.dmg` 兩個世代都係全 1 —— 傷害狠一倍，血量調得掂就唔好掂佢。

⚠ **豐緣第 1 章對 `hp` 極敏感**：0.92 → 66%、0.95 → 57%（0.03 差十點）。
城都第 2 章冇咁誇但都要細級距：1.18 → 76%、1.22 → 70%。

唔係城都豐緣有問題。

**魔鬼：特登唔校（老細 2026-08 拍板）。** 現有嗰個逐個地區都有嘅魔鬼模式
**會喺三世代改版嘅階段 5 取消**，變成一次過打三個地區所有 boss 嗰個
24 館通天塔。所以而家校魔鬼＝校緊一個就嚟拆走嘅模式，**唔好做**。

留低做參考：城都 10000 局量到 52/45/28/41/49/26/38/38，大致同關都嗰條線一樣、
後半仲緊啲（困難嗰邊校 `GEN_TUNE`，魔鬼順手食埋）。豐緣魔鬼冇量過，亦都唔使量。

## ✅ 決定咗：v41 困難後半鬆咗 —— **唔調返**，唔好再「修」

v41 加咗兩樣玩家向嘅嘢：**打低對手一隻之後有免費換人**、同埋**道具袋**
（厲害傷藥／復活藥丸／技能升級器，寶箱同商店拎到）。兩樣都係設計上要求嘅
「加強續戰力」，所以通關率升係預期之內，但**升幅比估計大**。

3000 局・困難（同一份 `ACT_TUNE`，淨係差呢兩個功能）：

| 章節 | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 | 四天王 |
|---|---|---|---|---|---|---|---|---|---|

## 圖鑑資料同精靈圖（`gendex.py` / `fetchdex.py`）

三世代改版嘅階段 1 加咗呢兩個。**235 行圖鑑資料同 386 張圖冇人手打過**
—— 人手打係幾萬個 token 嘅輸出，一定有錯，錯咗改又要再燒一次。

```bash
python3 tools/gendex.py fetch    # 落 PokeAPI 資料（cache 落 tools/.cache/）
python3 tools/gendex.py check    # ⭐ 攞現有關都 151 隻對返啲規則，證明冇砌錯
python3 tools/gendex.py apply    # 寫入 index.html（夾喺 marker 中間，可重跑）
python3 tools/fetchdex.py        # 落圖，出三個 assets/dexspr-genN-v1.js
```

⚠ `pokeapi.co` 俾呢個開發環境嘅 egress proxy 擋咗（403），
所以行緊官方靜態鏡像 `PokeAPI/api-data` 嘅 raw.githubusercontent。
同一份 JSON，連 URL 結構都一樣。

**`check` 係最有用嗰個。** 佢用現有關都 151 隻做標準答案，逐項對返
生成規則。而家嘅成績（改咗規則就要重跑，數唔應該變差）：

| 項 | 唔啱 | 點解 |
|---|---|---|
| 進化鏈 | **0/151** | — |
| 屬性 | 1/151 | 暴鯉龍（水/飛）現有寫「空」，係人手調嘅 |
| 階級 `s` | 5/151 | 拉達、皮卡丘、臭泥、伊布、快龍，都係人手評嘅強度 |
| 中文名 | 2/151 | 尼多後／尼多利諾 係舊譯，API 出新官方譯名 |

反推出嚟嘅兩條規則寫喺 `gendex.py` 個註解度，連埋憑證：

- **屬性**唔係「揀第一個」，係跟一個**優先次序**（`TYPE_RANK`）。
  例如磁怪（電/鋼）出「鋼」、迷唇姐（冰/超）出「超」、呆呆獸（水/超）出「水」。
- **階級 `s`** 唔係鏈嘅深度：單階算 3（大蔥鴨嗰批「單階強者」）、
  兩階鏈係 1→3（跳過 2）、三階先至 1→2→3、官方標住 baby 嘅算 1。
  而且**只計同一個世代入面嗰段鏈** —— 大鋼蛇喺城都池入面自己就係單階強者，
  唔應該當佢係大岩蛇（關都）嘅第二階。

⚠ **圖源同計劃書寫嘅唔同。** 計劃書話 `firered-leafgreen`「1-386 全齊」，
**實測係假嘅**：個資料夾只有 153 張，152-385 全部 404。而家用同一代嘅
`emerald`（385/386 齊），呆火駝（322）由 `ruby-sapphire` 補。

## 加新嘅地圖節點圖示

手機上載出嚟嘅係 JPEG，「透明背景」其實係被畫成灰白棋盤格燒死咗入去，
要還原返真正嘅 alpha。`pixicon.py` 幫你搞掂：

```
python3 tools/pixicon.py 圖片.jpeg --name rest --preview /tmp/p.png
```

`--name` 係 `index.html` 入面 `NODE_IMG` 嘅 key：
`mob` `elite` `rest` `shop` `chest` `unknown` `boss` `lock`。
腳本會 print 一行 `rest:'data:image/png;base64,...',`，抄入 `NODE_IMG` 就得；
`NODE_IMG` 冇嘅 key 會自動用返 `NODE_ICON` 嗰個 emoji，所以可以逐個逐個換。
記得開 `--preview` 用肉眼核對一次（預覽用返節點嘅深藍底色）。

圖示規格：1024×1024、透明底、一個檔一個圖示、主體用淺色、粗描邊、
**要有一圈完整嘅深色描邊包住**（腳本靠佢分開圖示同背景光暈）。
