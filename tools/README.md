# 爬塔平衡模擬器

呢個資料夾**唔屬於遊戲本體**。`index.html` 唔會載入呢度任何嘢，玩家永遠見唔到。
純粹係開發時用嚟調數值嘅工具。

## 做咩用

改爬塔難度嘅時候，靠自己試玩幾局係量唔準嘅 —— 通關率 50% 定 65%，
玩十局都分唔出。呢個模擬器用**遊戲本身嘅戰鬥引擎**跑成千局，直接量到真實通關率。

模擬嘅係一個「識玩但唔會神操作」嘅玩家：

- 每回合揀期望值最高嗰招（命中率 × 傷害，打弱點加權）
- 上場嗰隻血少過兩成、而有健康隊友就換人
- 獎勵優先攞遺物 > 招式強化 > 新招 > 骰晶片
- 遺物滿咗（8 件）就掉最冇稀有度嗰件，新嗰件唔夠好就索性唔換
- 進化唔到嘅寶可夢夠場數就特訓，血同傷害隨機揀一樣
- 四天王之間有隊友低過七成血、又買得起就買補給
- 商店有錢就買，血少就買傷藥
- 走地圖時隨機揀下一個節點

所以出嚟嘅數字係一個**中間水平**：識用屬性剋制、換人時機同骰子工房配骰嘅人會高過呢啲數，
求其亂打會低啲。

## 點跑

第一次要裝 Playwright（只需做一次）：

```bash
cd tools && npm install
```

### 量度而家嘅通關率

```bash
node tools/measure.mjs            # 1200 局，困難
node tools/measure.mjs 1400 0     # 1400 局，困難
node tools/measure.mjs 900 1      # 900 局，魔鬼
```

輸出：

```
章節   行到    打低    通關率   遺物/章
第 1 館   2500   1113     45%    2.46
第 2 館   1113    509     46%    2.26
第 3 館    509    255     50%    0.89
第 4 館    255    111     44%    0.04

四天王    111     43     39%    （4 連戰 + 冠軍）

四館全通：4%　真・全通（連冠軍）：2%

四天王入場：1206.9 金・8 件遺物・平均買 2.1 次補給
陣亡位置：天王1 0　天王2 1　天王3 2　天王4 8　冠軍 57
```

「通關率」＝ 行到嗰章嘅局數入面，成功打低道館主嘅比率。
途中俾雜魚打死都當冇通關（因為一樣打唔到道館主）。

「遺物/章」係**淨增長**。遺物有上限（`RELIC_MAX`，而家 8 件），
多數局第 2-3 章就已經滿曬，所以第 3、4 章嘅數字自然會跌近零 ——
唔係代表冇遺物拎，係代表之後每一件都要換走一件。

「陣亡位置」睇得出四天王段落邊度先係真牆。而家係冠軍。

### 試唔同數值（唔使改 index.html）

```bash
N=800 node tools/sweep.mjs '[
  {"dmg":{"all":1.0}},
  {"dmg":{"all":1.0},"dmgAct":[1,1,1,1.15]},
  {"dmg":{"all":1.1},"hp":{"all":1.05}}
]'
```

倍率 `1.0` 就係 `index.html` 而家嘅數值。可以調嘅嘢：

| 欄位 | 意思 |
|---|---|
| `dmg` | 敵人傷害倍率，`{all:1.2}` 或者逐個 tier `{mob:1.1, gym:1.3}` |
| `hp` | 敵人血量倍率，寫法同上 |
| `dmgAct` | 再按章節乘一次，`[第1章, 第2章, 第3章, 第4章]` |
| `hpAct` | 同上，血量版 |
| `post` | 每場勝利回幾多血（最大 HP 百分比） |
| `rest` | 篝火回血 |
| `badgeHeal` / `badgeHp` | 拎徽章時回血 / 加最大 HP |
| `diff0` | 覆蓋「困難」難度嘅倍率，例如 `{"heal":0.9}` |
| `diff1` | 覆蓋「魔鬼」難度。`hp` / `dmg` 可以寫 4 格陣列逐章唔同 |
| `set` | 直接寫死某個 tier 嘅陣列，用嚟單獨郁一章：`{"gym":{"nm":[…],"hp":[…]}}` |

量魔鬼要開埋 `DIFF=1`：

```bash
DIFF=1 N=2000 node tools/sweep.mjs '[{"diff1":{"hp":[0.93,0.93,1.3,1.3]}}]'
```

搵到啱嘅組合之後，先手動改返 `index.html` 入面 `TIER` 嗰個表，再跑 `measure.mjs` 確認。

## 樣本數要跑幾多

**跑 500 局同跑 1400 局，用嘅 AI usage 一模一樣**（輸出都係同一舊細細嘅 JSON），
分別只係電腦行耐啲。而細樣本雜訊大，反而要多試幾轉先調得準 —— 嗰啲來回先真係燒 usage。

| 局數 | 時間 | 第 4 章樣本 | 誤差 |
|---|---|---|---|
| 500 | ~25s | ~100 | ±10% |
| 1400 | ~68s | ~280 | ±6% |

所以**建議用 1200-1400**。要留意第 3、4 章嘅樣本數細好多（因為多數局數行唔到咁遠），
數字跳 ±5 點係正常，睇趨勢唔好睇單次。

## 目前目標

目標係一個**範圍**，唔係一個點 —— 第 3、4 章嘅樣本數細（多數局數行唔到咁遠），
量到嘅數字本身就會跳 ±5 到 ±10，追死一個數字係追緊雜訊。

| | 第 1 館 | 第 2 館 | 第 3 館 | 第 4 館 | 四天王 |
|---|---|---|---|---|---|
| 困難 | 35-50% | 30-45% | 30-45% | 30-45% | ≤50% |
| 魔鬼 | 25-40% | 20-35% | 20-35% | 20-35% | ≤50% |
| 遺物 | 第 1-2 章每章 2-3 件，之後上限 8 件封頂 | | | | |

「四天王」＝ 打低四個道館主嘅局數入面，有幾多完成 4 連戰 + 冠軍。
呢段冇篝火冇商店，每場之間淨係回 15% HP，係一場消耗戰 ——
唯一嘅補給就係開戰前用金幣買（`E4_HEAL_COST`，價錢每用一次升一級）。

四天王之前實測 70%（高過 ≤50%），加咗遺物上限之後跌到 ~38%，入到範圍。
留意呢個數字樣本天生細：跑 3000 局先得 ~90 局行到四天王（誤差 ±5），
要準啲就要 8000 局以上。要再郁嘅話，旋鈕有 `E4_HEAL`、`E4_HEAL_COST`、
同 `TIER.e4` / `TIER.champ`。

## 調數值嗰陣要記住兩件事

**一、郁一章會連帶影響之後嗰幾章。** 前面難咗，行得到後面嘅隊伍本身就強啲，
所以後面反而會顯得易咗。試過第 2 章由 46% 拉落 36%，第 4 章就自己彈上 48%。
要一次過睇齊四個數，唔好逐章追。

**二、魔鬼唔可以同困難用同一組倍率。** 魔鬼嘅難度嚟自「館主全程帶 3 隻」，
但呢個優勢淨係喺第 1-2 章存在（困難嗰陣先得 2 隻）；第 3-4 章困難一樣係 3 隻。
所以一個數行到尾嘅話，魔鬼第 3-4 章會反而易過困難（實測 63% / 56%）。
`DIFFS` 入面 `hp` / `dmg` 因此支援寫 4 格陣列逐章唔同。

**三、魔鬼後兩章對倍率極度敏感。** 行到第 3 章嘅係最強嗰 7%，人數本身好薄，
加少少就冧一大片：`hp` 由 0.93 加到 1.20 就令第 3 章由 63% 跌到 15%
——即係 0.05 嘅級距抵得上十幾點通關率。調嘅時候一次行 0.05，唔好跳 0.2。

## 檔案

| 檔案 | 做咩 |
|---|---|
| `simlib.js` | 模擬器本體，注入到遊戲頁面度行 |
| `_boot.mjs` | 開瀏覽器、載入 `index.html`、注入 `simlib.js` |
| `measure.mjs` | 量度通關率 |
| `sweep.mjs` | 一次過比較幾組數值 |
| `test-features.mjs` | 遺物上限／特訓／四天王補給／傷害尾巴嘅回歸測試 |

| `pixicon.py` | 將上載嘅像素畫節點圖示轉成 data URI |

## 加新嘅地圖節點圖示

手機上載出嚟嘅係 JPEG，「透明背景」其實係被畫成灰白棋盤格燒死咗入去，
要還原返真正嘅 alpha。`pixicon.py` 幫你搞掂：

```
python3 tools/pixicon.py 圖片.jpeg --name rest --preview /tmp/p.png
```

`--name` 係 `index.html` 入面 `NODE_IMG` 嘅 key：
`mob` `elite` `rest` `shop` `chest` `unknown` `boss` `lock`。
腳本會 print 一行 `rest:'data:image/png;base64,...',`，抄入 `NODE_IMG` 就得；
`NODE_IMG` 冇嘅 key 會自動用返 `NODE_ICON` 嗰個 emoji，所以可以逐個逐個換。
記得開 `--preview` 用肉眼核對一次（預覽用返節點嘅深藍底色）。

圖示規格：1024×1024、透明底、一個檔一個圖示、主體用淺色、粗描邊、
**要有一圈完整嘅深色描邊包住**（腳本靠佢分開圖示同背景光暈）。
