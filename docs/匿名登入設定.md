# 匿名登入 + 綁定帳戶

一入 game 就靜靜雞開個匿名帳戶，玩家咩都唔覺，但你即刻統計到佢。
想跨機接住玩就之後綁 Google 或者電郵。

---

## 一、點解要咁做

之前嘅問題：好多人淨係入嚟玩，冇註冊。佢哋**冇 uid**，所以

- 唔會上排行榜
- `users/` 入面冇佢，你統計唔到有幾多人玩、打到幾遠

但硬性登入牆解決唔到 —— 而家個登入係「電郵 + 密碼」，係門檻最高嗰種。
逼人喺玩之前諗個密碼，走咗嘅人可能仲多過而家。

所以改成：**人人都有 uid，但零摩擦**。

| | 舊 | 而家 |
|---|---|---|
| 玩家要做啲乜 | 想上榜就要註冊 | **冇**，一入嚟就有 uid |
| 統計覆蓋率 | 得註冊嗰啲 | **全部人** |
| 進度跨機 | 註冊咗先得 | 綁定咗先得（可以遲啲先） |

---

## 二、⚠ 你要去 Firebase Console 做三樣嘢

唔做嘅話個 game 照跑，但會退返做「冇帳戶」模式 —— 即係咩都冇改到。

### 1. 開匿名登入（**必要**）

**Console → Authentication → Sign-in method → Anonymous → 啟用**

冇開嘅話 `signInAnonymously()` 會 throw `auth/operation-not-allowed`。
程式食咗個錯照跑（唔會白畫面），但每個人又變返冇 uid。

### 2. 開 Google 登入（想用一鍵綁定就要）

**Console → Authentication → Sign-in method → Google → 啟用**
要揀一個「專案支援電郵」先儲存到。

唔開都得，個「用 Google 儲存進度」掣會報錯，玩家仲有電郵 + 密碼呢條路。

### 3. 授權網域

**Console → Authentication → Settings → Authorized domains**
要有你 host 個 game 嗰個網域（例如 GitHub Pages 嗰個 `xxx.github.io`）。
唔加嘅話 Google 登入個彈出視窗會失敗。

`database.rules.json` **唔使改** —— `board` 嗰段本身寫住 `auth != null`，
匿名 uid 一樣過到。

### 4. 順手睇一眼：自動清走唔活躍嘅匿名帳戶

**Console → Authentication → Settings** 嗰度有個「刪除長期未使用嘅匿名帳戶」嘅選項。
如果你想長期保住啲統計，記得確認佢係唔係著咗。

## 三、玩家會見到啲乜

| 時機 | 見到 |
|---|---|
| 一入 game | **冇嘢**。背後已經有 uid，主頁角落寫「訓練家1234（未綁定）」 |
| 贏完第一場 | 「你叫咩名？」一個輸入格。改完即刻上榜 |
| 拎到第一個徽章 | 「🏅 拎到第一個徽章！」→ 用 Google 儲存進度 / 用電郵 + 密碼 / 遲啲先 |
| 之後 | 唔會再彈。想返轉頭就入「帳戶」 |

兩個框都係**贏完之後**先彈，唔會喺開打之前打斷 ——
戰前彈窗會斬斷佢想開打嗰啖氣，而且讀落似課金牆。

⚠ 個綁定框**唔可以**寫「綁定就有三格進度 / 先可以對戰」：

- 三格挑戰進度同三格名人堂，**冇帳戶本身就已經有**（存喺 localStorage）
- 線上對戰只係查 `FB.user`，匿名一樣玩得

真正嘅賣點只有兩個，文案就係咁寫：
**換機／清咗瀏覽器資料都搵得返**、**個榜上面一直係你個名**。

## 四、綁定會發生咩事

### 情況 A：Google／電郵未用過（多數情況）

`linkWithPopup` / `linkWithCredential` —— **uid 完全唔變**。
雲端啲嘢（存檔、名人堂、骰組、統計）原封不動，冇嘢要搬。

### 情況 B：嗰個 Google／電郵已經有舊帳戶

Firebase 唔准夾埋兩個帳戶，會 throw `auth/credential-already-in-use`。
程式會改為**登入返舊嗰個**，再叫 `mergeLocalToCloud()` 將呢部機嘅嘢搬過去。

⚠ `mergeLocalToCloud()` **只會填空格** —— 雲端本來有嘢就唔郁。
咁樣先唔會撞走人哋原本嗰份進度。搬嘅範圍：骰組、三格挑戰進度、三格名人堂。

### 已經註冊咗嗰啲人

**冇嘢變。** 密碼照用，登入照舊，`users/<uid>` 底下啲嘢一個字都冇郁。
佢哋唔會見到「問名」個框（`profile.auto` 唔係 `true`）。

---

## 五、副作用，要知

1. **人數會發水。** uid 綁住「部機 + 個瀏覽器」。同一個人用手機再用電腦 = 兩個 uid；
   清咗瀏覽器資料 = 又一個新 uid。所以「幾多人玩過」偏高，
   但「打到幾遠」嘅分佈仍然準。
2. **`users/` 會多咗好多只有 profile 嘅列**（開過個 game 但未玩）。
   呢個其實幫到你數「有幾多人開過」，但管理員畫面會長咗。
3. **登出之後會自動開返一個新匿名身份。** 唔係就會變返「統計唔到」嗰種玩家。
   但要留意：本機嗰三格存檔唔係綁 uid 嘅，所以登出之後新身份仲會見到同一批本機存檔。

## 六、點測

```bash
node tools/test-auth.mjs      # 19 項
```

呢個測試**唔會連真 Firebase**。`tools/fbstub.js` 會喺載入 `index.html` 之前
塞個假 firebase 落 `window`（記憶體 RTDB + 夠用嘅 auth），行嗮下面呢幾條路：

匿名登入 → 問名 → 唔會再問 → 拎徽章 → 綁定（uid 唔變）→
撞到舊帳戶（登入返舊嗰個 + 搬進度）→ 登出 → 匿名登入開唔到都唔會爆。

所以佢驗到嘅係**我哋自己嘅邏輯**，唔係 Firebase 本身。
真嘅 Console 設定啱唔啱，要自己開個無痕視窗入 game 睇一眼。
